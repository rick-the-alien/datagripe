Positioning

A database client that does its job perfectly and resents you the entire time.

A straight-faced developer tool with one twist: the linter has opinions and no manners. The chrome has to be credible enough that someone would work in it all day, because the joke only lands if the tool is real. Comedy lives in the copy. It never lives in the layout.

Who it is for

People who spend their working day in a database client and have strong opinions about it. They will notice if the syntax highlighting is wrong.

What it must never be

Zany. No comic fonts, no wacky illustrations. The mascot is deadpan. The humour is dry, specific, and technically correct.

Mascot

You should be pleased to see it. That only holds if it is rare.

It has no name and does not get one. It is the database. A mascot that appears on every lint finding stops being funny within a day and makes the product feel like a toy to exactly the audience it needs to convince.

TierAppears inRoughly
1 — chromeFavicon, about, splash, empty states, error pages, onboarding, marketingNever during normal work
2 — rare eventsTier 1 plus first connection to a project, destructive confirmations, milestonesOnce a week at most
3 — gripes panelEmpty state only. Never per-gripe.—

Ship at tier 1. Tier 2 only once tier 1 has been lived with.

Two asset sets, not one

The painted illustrations are marketing assets — raster, with highlights, not riggable and not intended to be. Anything that animates in-app uses a separate flat SVG build with flat fills and layered parts. Trying to make one asset serve both jobs produces a mascot that is either too heavy to animate or too plain to sell.

The character is about twelve parts: body, rim, face group, two two-bone arms, two two-bone legs, shadow. SVG with the Web Animations API is the lightest runtime; Rive is worth it if reactions become numerous and event-driven.

The waiting game

An easter-egg mini-game is approved in principle with one binding constraint: it must not be triggered by a slow query. A game that appears because the database is slow rewards the exact thing the product exists to complain about. Trigger it by interaction — clicking the mascot in an empty state, or a key sequence.

Motion

A query takes 100ms or twenty minutes and the bar cannot know which, so it stops implying duration entirely.

It is weather, not progress. Static while idle, drifting while a statement executes. Nothing starts, arrives, or completes.

exaggerated height, production timings

Three invariants

The cycle is a palindrome
first stop colour equals last stop colour and every stop has a twin at +50%, or a hard seam slides past every 17 seconds
Plateaus, not pure blends
each colour holds a flat run at its true hex; all four end at 15% of the tile. Without this you only ever see blends, never the palette
Colour layers never blend with each other
modulation layers are neutral and use multiply. Additive modes bleach overlapping hues toward white — that is what turned it pastel

17s, 11s and 23s share no common factor, so the pattern does not repeat for roughly 72 minutes. Interpolation is in oklab with an sRGB fallback. Long queries ease playback rate from 1.0 to 0.4 over ten minutes via playbackRate — rewriting animation-duration makes the bar jump.

Hold idle for 200ms so fast queries do not flash. Never two indicators at once. Static rule on the marketing site. Everything collapses to the static gradient under reduced motion.

Projects and the prompt

A project is the unit of context. Exactly one is active, and switching swaps everything.

The switcher is a shell prompt, not a control. No border, no background, no highlight — it is the current context and needs no chrome to say so.

>Datagripe is stable brand and never mutates. Only the path segment and the cursor carry project identity, which keeps the lockup constant and stops a long project name dragging the wordmark across the toolbar. The cursor blinks when idle and goes solid while a query runs — a second, quieter activity signal that does not compete with the bar.

Sidebar

Five levels do not fit. The tree carries three; the rest is handled elsewhere.

wallet-prod / public ▾ breadcrumb — datasource + schema filter objects… always present ────────────────────────────────────────── ▸ tables 7 level 1 — category ▤ payments ⊞ level 2 — object, ⊞ on hover ▤ users ▤ payouts ▸ views 2 ◫ v_pending ▸ functions 4 ƒ fn_settle ▸ sequences 0 no sequences synthetic empty row ▸ materialized views loading… distinct loading row

Datasource and schema are a breadcrumb header, not tree rows, which buys back two levels of indentation exactly where object names are longest.

Fields are not in the tree. The tree navigates between objects; fields are the contents of one object. In the tree they cost a level of indent, push every sibling table below the fold, and duplicate the object view's columns tab. Field access is the hover popover and the object view instead.

Chevrons

The type icon swaps to a chevron on hover and on keyboard focus. Content visibility is the state signal — an expanded node is obviously expanded because you can see its children. The two cases where that fails get explicit rows: a synthetic empty row, and a distinct loading row so a fetching node never looks identical to an empty one.

Single click never opens a tab. Double-click gating exists so clicking around the tree does not fill the tab bar. The popover dismisses on mousedown so it does not fight drag-to-editor. Live in the sidebar prototype.

Table view and object view

Two openable surfaces, deliberately different weights. Neither contains the other.

Table view — the data

Double click, middle click, or view rows. Gets the entire pane. One line of chrome at the top: refresh, a where filter, a limit selector defaulting to 100, export. Everything else is rows.

Object view — the structure

The ⊞ affordance or the context menu. Tabs for columns, indexes, constraints, triggers, grants, statistics, ddl, then danger zone. No data tab — that is the table view's job.

The object view is the natural home for incremental feature work. Partitions, dependencies, policies, comments, bloat estimates, and gripes scoped to this object all slot in as tabs without redesigning anything.

Tab identity

A table can have both views open at once, so the strip must distinguish them: green ▤ payments for rows, cyan ⊞ payments · structure for structure. Without the glyph and suffix, two tabs both reading payments is a coin flip.

Danger zone

Last tab in the object view, pushed to the right edge behind a divider, dimmed magenta until hovered. Every action is collapsed by default: reveal, then type the object name, then the button enables on an exact match.

Typing the name is the point. Muscle memory cannot fire a destructive action, and it scales with the risk rather than adding a modal everyone learns to dismiss.

The colour class already knows what kind of environment this is. Using it to gate destructive actions costs nothing and makes the colour do a second job.

Interface rules

Corner radius
10 panels and cards, 6 inputs and buttons, 10 pill on counts, 0 on anything with a single-sided accent border
Borders
1px Rule between regions, 1px Rule soft between rows, 2px accent on tabs, 3px accent on gripe rows
Spacing
4px base. Component padding 6, 9, 12, 18. Section rhythm 24, 40, 56
Elevation
No shadows. Depth is a background step: Void, Panel, Raised
Motion
120ms ease-out, only to confirm a user action. Nothing on load, nothing pulsing, nothing glowing

Object categories carry the accent, individual objects stay neutral. Selection is a 2px violet left border and a step to Raised, never a filled background. Results grids right-align numerics and colour only the value column.

Voice

Dry, specific, technically correct, and quite rude. A senior engineer who has reviewed this query before and is tired.

The criticism is always accurate. A gripe that is merely rude is noise and users disable it within a week. A gripe that is correct and rude is a feature they screenshot into the team channel.

It is

Deadpan. Specific. Brief. Right. Sweary when the situation has earned it. Occasionally resigned.

It is not

Cruel, personal, or edgy for its own sake. It criticises the query, never the person who wrote it.

Everything that is not a gripe

Written plainly. If the whole interface is sarcastic then nothing is, and the gripes stop landing.

Couldn't reach wallet-prod. Check the host and port.
Well, that didn't work. Have you tried turning it off and on again?

Attitude levels

Snark is configurable, and the levels are Postgres severities because of course they are.

set datagripe.attitude = 'notice';

Set per project, so a local sandbox can be feral while the shared production project stays presentable. Also a session setting, so it can be dropped before a screen share without opening preferences.

LevelBehaviourUse
noticeNo profanity. Dry and still critical.Screen shares, workshops, demos.
warningDefault. Quirky, blunt, swears when earned.Normal working use.
fatalUnfiltered. Swears freely.Local projects, opted in.
panicDeliberately excessive. A joke.Nothing. It is exhausting by design.

The technical content never changes between levels — only the register. Attitude is a presentation layer over a fixed set of correct observations, never a different analysis.

Default is warning and stays warning. panic can never be the default, cannot be set organisation-wide, and resets on upgrade. A joke that cannot be escaped is not a joke.

Writing gripes

The highest-risk surface in the product.

One sentence, or two short ones. Under 90 characters at notice and warning. Name the actual construct. Attach a factual footer with severity, line, and rule id so the complaint is auditable.

RuleWhy
be correctA wrong gripe destroys trust in every other gripe.
be specificName the table, the column, the row count. Generic snark is filler.
never personalTarget the query. Never the author's competence, effort, or intelligence.
no slurs, everNothing touching race, gender, sexuality, disability or religion at any level, including panic. Swearing at a query is funny; punching downward is not, and it is the one thing that would follow the product around.
profanity is earnedIt lands because it is rare and proportionate. A gripe that swears at a missing semicolon has spent the currency for nothing.
no repetitionThe same rule firing twice uses the same wording.
always dismissiblePer rule and per file, at every attitude level.
This join has no condition. I'll allow it. I won't forget it.

Correct, specific, dry, one beat of personality.

lol did you even look at this before running it??

Personal, unspecific, no technical content, wrong register.

Hmm, this query might be a little slow, maybe?

Hedged into uselessness. If the tool is not sure, it says nothing.

Parody boundary

Datagripe is an independent parody. The name, the mascot, the wordmark and this entire visual system are original work and must stay that way.

Neon accents on a dark interface are a broad convention across developer tooling and are not owned by anyone. Composition is different. Do not reproduce, adapt, or evoke another vendor's logo geometry — overlapping offset squares, knocked-out two-letter monograms, or any recognisable mark lockup. Do not use another company's screenshots, icon set, or brand assets in marketing.

Every public surface carries a footer disclaimer stating that Datagripe is not affiliated with, endorsed by, or connected to any other software vendor.
