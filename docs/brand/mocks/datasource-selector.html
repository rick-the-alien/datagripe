Why the second segment is not called "schema"

A project holds datasources of different engines. Postgres has schemas, MySQL calls the same level a database, Redis has numbered keyspaces, SQLite has one namespace and a file path. A breadcrumb hard-coded to "schema" is wrong three times out of four, so the segment takes its label from the active engine and the tree rebuilds to match — categories are tables / views / functions / sequences on Postgres and keys by prefix on Redis.

Engine identity stays neutral

Engine chips are neutral monograms on Raised, never accent colours. The four accents are already spoken for by project class, and production magenta is meant to be the only permanent magenta in the interface. If MySQL were orange and Redis were red, the safety colour would be competing with decoration within a few connections.

Connection status uses shape as well as colour, per the accessibility rule: filled dot connected, hollow ring disconnected, magenta ring errored.

New datasource is a tab

Consistent with table view and object view. It survives you going off to find credentials, you can have two open while comparing settings, and it does not trap focus the way a modal does. The form asks for the project class explicitly rather than inferring it, because that field decides whether the danger zone gates on the table name or the project name.

The class field is where a real question surfaces. If a project can contain both a production and a local datasource, the project-level safety colour is a lie — statements run against a datasource, not a project.

Three ways to resolve that

OptionWhat it meansCost
class on projectA project may not mix classes. Adding a local datasource to wallet-prod is rejected.Simplest and safest. Forces more projects, which is arguably correct — a project is the unit of context.
class on datasourceThe prompt becomes >Datagripe:wallet-prod/wallet-primary_ and the cursor takes the datasource colour.Accurate, but a longer prompt and two things to read before you trust the colour.
project takes the worstClass stays on the datasource; the project displays the highest-risk class it contains.Never under-warns, but over-warns constantly — every project with one prod connection goes magenta.
My recommendation is the first. It keeps one colour in one place, and "this project is production" is a cleaner mental model than "this project is production right now depending on which connection is selected". The cost is more projects, and projects are cheap.

Details worth keeping

Selecting a disconnected datasource connects it — the activity bar drifts and the status line says so rather than silently failing. The datasource popover lists disconnected entries normally rather than hiding or greying them out, because "connect to the thing I have not used today" is the common case, not an error.

Both popovers get a filter box above about eight entries. Switching datasource resets the second segment to that engine's default namespace rather than trying to preserve public across engines where it may not exist.
