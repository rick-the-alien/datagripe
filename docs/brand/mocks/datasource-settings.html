Width

Three things fix it together, and none of them is stretching the inputs.

The field grid gains columns. repeat(auto-fit, minmax(168px, 1fr)) means three fields on a medium pane and five on a wide one, with each field staying a sane width. The form fills naturally instead of being padded.

A right rail earns the leftover space. Connection state, the resolved connection string, and the test log. On a connection form that is exactly the information you want while filling it in, and it turns dead space into the reason the pane is wide.

The column caps out. Past roughly 880px the form stops growing and the rail takes the rest. A settings form that keeps widening at 2000px looks worse than one that stops.

The rail collapses below about 900px of pane width and its content moves under the form. Try narrow pane — nothing is lost, it just stacks.

The two save buttons

This was the thing I would fix first, ahead of width. save directory and save in the same form means one of two things is true and the user cannot tell which: either the directory saves separately for a reason, or it is a leftover. Both readings make someone click both buttons to be safe.

Here there is one save. If the export directory genuinely needs separate server-side validation, that is a validation step, not a save — so it becomes a check path action next to the field, with the result inline, and the single save at the bottom commits everything.

Read-only means read-only

The original says "Defined by server configuration — read-only" and then offers editable-looking fields and a save button. Switch to predefined above: fields go dashed and dimmed, the engine picker locks to the current engine, toggles disable, and the footer replaces save with an explanation of where the value comes from. Nothing lies about what you can do.

What is already right

The prompt reads well and the class colour on the project name works. The status bar is doing real work — connection, schema, project, class, update state, gripe count — and the dashed mock pill is a good pattern for a non-production mode. Scratchpad empty-state copy is genuinely useful rather than decorative. The engine picker with monogram chips is the right call and stayed neutral.
