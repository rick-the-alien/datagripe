connected — 3 gripes

Sidebar and tabs are fully decoupled

The sidebar is browsing and management. It never changes where a document runs, and switching documents never moves the sidebar. Note the header says browsing, not the current target — the two are different facts and the interface stops pretending otherwise. In the split above, the left pane runs against wallet-primary and the right against ledger-core, while the tree sits on whatever you were last looking at.

The chip group

Target first, then the actions. You read where before what, and it puts the most destructive control — run all — furthest from the target selector so you cannot fat-finger one while reaching for the other.

ElementBehaviourKey
targetClass dot, datasource, namespace. Click to rebind. Truncates from the left at narrow widths.⌘⇧T
saveOccupies a reserved slot — appears only when dirty, but the slot is always there.⌘S
runStatement at the cursor, or the selection if there is one.⌘↵
run allEvery statement in the document, in order. Confirms on a production target.⌘⇧↵
The reserved slot matters more than it sounds. If the save glyph simply appeared when the buffer went dirty, the run buttons would shift sideways the moment you typed a character — and you would learn to aim at a moving target. Reserving the width costs 24px and removes the jitter entirely. Toggle mark dirty and watch that nothing moves.

The tab itself also carries a dirty dot, which is the convention people already know. The chip-group save is the affordance; the tab dot is the status.

Undefined is the starting state

A new or newly opened document has no target. It is never inherited from the sidebar and never defaults to anything. Run and run all are disabled, the chip reads in Focus Violet rather than a class colour, and the left edge rule goes dashed — so an unbound document is visibly unbound while you are typing in it, not only when you try to execute.

This is the one place a convenience default would be actively dangerous. Inheriting the sidebar target means browsing production to look something up silently re-points every new file at production. Explicit, always.

The edge rule

Two pixels of class colour down the left of the editor, for the whole time the document is open. Peripheral vision picks it up while you are looking at code, which is where you actually are — a chip in the corner requires you to go and check. Magenta down the side of a buffer is a different feeling from magenta in a corner.

Broken and stale targets

StateChipBehaviour
unsetViolet, dashed dot, "set target"Run disabled. Never falls back.
brokenMagenta, struck throughDatasource deleted or renamed. Run disabled, one click to rebind. Never auto-resolves to a near match.
stale namespaceClass colour, namespace in magentaDatasource alive, schema gone. Keeps the datasource binding, prompts for namespace only.

Narrow widths

The chip group is pinned and never scrolls with the tabs — the tab strip scrolls underneath it. Below roughly 320px of pane width the target truncates to class dot plus datasource initial; the actions never collapse, because a hidden run button is worse than a truncated label.

Two calls left for you

Run all on production. Currently a confirm. The alternative is that run all is simply unavailable on a production target and you must select the statements you mean. Harsher, and arguably right for a tool whose entire safety model is about not doing things to prod by accident.

Scratchpads. They are throwaway and local by nature, so pinning a target may be more ceremony than they deserve. The options are that they bind like everything else, or that they alone follow the sidebar — which would be the single exception to the decoupling rule and would need to be very visibly marked.
