Results tab and run controls

Results is an ordinary tab. It goes wherever the split layout puts it, including nowhere.

layout

It is just a tab

No docked panel, no collapsed strip, no special casing. The layout engine already does arbitrary splitting, so the results tab inherits all of it for free — below the editor, beside it, in a third column, or sharing a group so the two swap.

Try same group as editor and select the results tab: the editor is gone. That is the case the gutter buttons exist for, and it is a legitimate thing for someone to want on a small screen.

Gutter buttons carry the class colour

Every detected statement gets a play triangle — always visible on the statement at the cursor, revealed on hover elsewhere. It takes the target's class colour, so a magenta triangle sits beside the line you are about to run against production. The safety signal is at the point of action rather than in a corner. Switch to no results tab: running still works with nothing else on screen.

Two modes

Table and history. Messages is gone. Row counts and notices live in the timing readout — 1 row updated, 3 rows in 6 ms — and errors render in the body where the grid would be.

Dropping messages actually improves the error case. An error now occupies the space you were already looking at instead of hiding behind a mode you have to switch to. It keeps full server detail — message, the offending SQL with the position marked, and the SQLSTATE — because the alternative is a truncated string and a trip to the log.

Export and copy

Joined group, right aligned. Download writes a file in the current format, clipboard copies the same content, and the shared chevron sets that format for both. One setting, two destinations.

ControlActionNote
downloadFile in the current formatRespects the current filter and sort, not the raw result
clipboardSame content to the clipboardSelection if there is one, otherwise the whole set
chevronFormat menuSets the default for both, persists per project
One wrinkle worth knowing about early: the useful format sets are not identical. Markdown is excellent pasted into a ticket and pointless as a download; SQL inserts are useful both ways. If they diverge, the shared chevron has to become two.

Dropped for now

Run all no longer shows a per-statement selector. The timing readout says how many statements ran and the body shows the final result set. Multi-result navigation is a real feature and deserves its own design rather than a strip of sub-tabs bolted on.

Still open

Whose target. The toolbar reflects the focused editor. With results beside an editor rather than below it, focus is more ambiguous — clicking into the results grid must not re-point anything. It does not here, but that rule needs holding once the layout engine is real.

Save. Still ⌘S with the dirty dot on the tab. No button anywhere.
